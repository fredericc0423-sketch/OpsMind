
# OpsMind — AI-Powered Incident Diagnosis Agent

OpsMind is a local AI Agent prototype for IT service incident diagnosis, built with LangGraph, LangChain, Ollama, Chroma, FastAPI, and Docker.

It combines simulated monitoring metrics, application logs, and Retrieval-Augmented Generation (RAG) to produce evidence-based troubleshooting suggestions.

## 1. Features

- **AI Agent Workflow:** Uses LangGraph to manage multi-step reasoning and tool execution.
- **Tool Calling:** Allows the LLM to select monitoring, logging, and knowledge retrieval tools.
- **RAG Knowledge Base:** Retrieves troubleshooting instructions from operational runbooks using Chroma.
- **Conversation Memory:** Uses LangGraph Checkpointer to retain conversation state during a running process.
- **REST API:** Exposes diagnostic functionality through FastAPI.
- **Docker Deployment:** Supports containerized execution with a host-based Ollama service.
- **Structured Logging:** Records API requests, LLM execution, and tool activity.
- **Automated Tests:** Includes API and monitoring-tool tests using Pytest.

## 5. Quick Start

### Prerequisites

- Docker Desktop
- Ollama running on the host machine
- Qwen3 chat and embedding models

Download the models:

```bash
ollama pull qwen3:8b
ollama pull qwen3-embedding:0.6b
```

### Build the Docker image

```bash
docker compose build
```

### Build the vector index

```bash
docker compose run --rm opsmind python build_index.py
```

### Start the API

```bash
docker compose up -d
```

Visit:

http://127.0.0.1:8000/docs

Note: The Docker configuration uses `host.docker.internal` to access Ollama on the host. The example setup targets Docker Desktop.

## 6. API Example

Endpoint:

```text
POST /chat
```

Request:

```json
{
  "question": "Check order-service CPU usage, error logs, and relevant troubleshooting runbooks.",
  "thread_id": "demo-001"
}
```

Response structure:

```json
{
  "thread_id": "demo-001",
  "answer": "Diagnostic analysis generated by the agent."
}
```

The actual answer depends on the available tool results and LLM output.

## 7. Testing

Install development test dependencies:

```bash
python -m pip install pytest httpx
```

Run tests:

```bash
python -m pytest tests -v
```

## 8. Limitations

- CPU metrics and application logs currently use simulated data.
- Conversation state is stored in process memory and is lost after a restart.
- RAG uses a small demonstration runbook collection.
- The prototype is intended for learning, demonstration, and further development, not production incident response.
