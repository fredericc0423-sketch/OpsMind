# 数据库连接池耗尽故障

常见症状：
- API 响应时间显著增加。
- 日志出现 Connection pool exhausted。
- 日志出现 Database connection timeout。
- 请求超时或部分接口返回 500。

排查步骤：
1. 检查数据库连接池的最大连接数。
2. 检查当前活跃连接数与等待连接数。
3. 检查是否存在未释放的数据库连接。
4. 检查数据库慢查询。
5. 检查数据库 CPU、内存及连接数。

建议：
优先确认连接池是否耗尽，再排查慢查询和连接泄漏。
不要仅凭超时日志就认定根因。

# CPU 使用率过高故障

常见症状：
- 服务 CPU 使用率持续超过 90%。
- API 延迟增加。
- 服务吞吐量下降。

排查步骤：
1. 检查流量是否突然增加。
2. 检查 CPU 占用最高的进程和线程。
3. 检查是否存在死循环或异常重试。
4. 分析 CPU Profile。
5. 检查 GC 是否频繁发生。

建议：
结合流量、CPU Profile 和应用日志判断具体原因。

# API 响应时间过高故障

常见症状：
- API P95 或 P99 延迟升高。
- 请求超时增多。
- 用户反馈页面加载缓慢。

排查步骤：
1. 检查服务 CPU 和内存。
2. 检查数据库慢查询。
3. 检查下游服务响应时间。
4. 检查网络连接和超时配置。
5. 使用分布式追踪定位耗时环节。

建议：
优先定位延迟发生在哪个调用环节，而不是直接增加服务器资源。
